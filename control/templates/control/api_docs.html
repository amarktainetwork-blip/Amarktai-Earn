Authentication

Direct keys or verified channel identity.

Direct requests use Authorization: Bearer <api-key>. Keys are displayed once when an owner issues them; only a password hash is stored. RapidAPI requests use verified proxy identity headers.

Keep credentials private

Never place an API key in client-side code. Revoked keys fail closed immediately.

Request lifecycle

Idempotent jobs and accepted output.

  1. 1POST a product job with a unique Idempotency-Key.
  2. 2Receive 200 for completed deterministic work or 202 with a request ID.
  3. 3Poll GET /api/v1/requests/{request_id}.
  4. 4Read the result only after COMPLETED and QA acceptance.

Errors and limits

Structured, bounded and safe to retry.

401 authentication_failed

Credential is missing, invalid or revoked.

409 idempotency_conflict

The same key was reused with another payload.

422 invalid_payload

Input does not satisfy the product schema.

429 quota_exhausted

Plan quota or rate limit was reached.

503 economic_admission_rejected

Safe execution cannot preserve its floor.
